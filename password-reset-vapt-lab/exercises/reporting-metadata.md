# Reporting Metadata

The mappings below use the official OWASP Top 10 category names for 2021 and 2025.[1] [2] Severity ranges are suggested training ranges, not a substitute for context-based scoring.

| Vulnerability name | Affected endpoint/mode | Root cause | Impact | Remediation | OWASP 2021 | OWASP 2025 | Suggested severity | Evidence requirements |
|---|---|---|---|---|---|---|---|---|
| Client-supplied account identifier | `/api/reset`, `vulnerable-client-id` | The server trusts `username` or `user_id` from the request instead of deriving the account from the token. | A valid token for one account may change another synthetic account's password. | Derive the target user only from the server-side token record and reject conflicting identifiers. | A01 Broken Access Control; A07 Identification and Authentication Failures | A01 Broken Access Control; A07 Authentication Failures | High to Critical | TOKEN-A request for Alice, modified Bob request, responses, Bob login result, token metadata, and event record. |
| Missing token validation | `/api/reset`, `vulnerable-no-token` | The final password update does not enforce reset-token validity. | An attacker may change a known synthetic account password without reset authorization. | Require a present, hashed, valid, unexpired, unused, and unrevoked token before update. | A01 Broken Access Control; A07 Identification and Authentication Failures | A01 Broken Access Control; A07 Authentication Failures | Critical | Requests with missing, empty, invalid, and modified tokens, response codes, password-login proof, and events. |
| Token reuse | `/api/reset`, `vulnerable-token-reuse` | Successful use does not set `used_at` or otherwise invalidate the token. | A captured token can provide repeated reset capability. | Enforce single-use semantics in the same transaction as the password update. | A07 Identification and Authentication Failures; A04 Insecure Design | A07 Authentication Failures; A06 Insecure Design | High | First successful request, replay request, changed-password results, token row before/after, and events. |
| Old-token invalidation failure | `/forgot-password`, reset-token lifecycle | A new reset request fails to revoke older unused tokens despite a latest-token-only policy. | Several valid reset paths may remain active longer than intended. | Choose and document a policy; under latest-token-only, revoke older tokens when issuing a new token. | A07 Identification and Authentication Failures; A04 Insecure Design | A07 Authentication Failures; A06 Insecure Design | Medium to High | TOKEN-A and TOKEN-B metadata, validation results, policy statement, and event chronology. |
| Undocumented multiple active tokens | `/forgot-password`, `vulnerable-multiple-tokens` | Multiple outstanding tokens are accepted without a clear intended policy. | Ambiguous lifecycle can complicate revocation and incident response; impact depends on policy. | Document whether multiple tokens are intended and enforce expiration, binding, and single-use rules consistently. | A04 Insecure Design; A07 Identification and Authentication Failures | A06 Insecure Design; A07 Authentication Failures | Informational to High | TOKEN-A/B/C creation times, expirations, validation results, and the stated policy. |
| Token expiration not enforced | `/api/reset`, `vulnerable-expiration` | Stored `expires_at` is ignored during validation. | A token remains usable beyond the intended authorization window. | Reject tokens when current time is at or beyond `expires_at`; test clock and timezone handling. | A07 Identification and Authentication Failures; A04 Insecure Design | A07 Authentication Failures; A06 Insecure Design | High | Token metadata, time of request, expired response comparison, and `reset_token_expired` event in secure mode. |
| Password-policy bypass | `/api/reset`, `vulnerable-no-policy` | Reset endpoint omits server-side length, common-password, and strength validation. | Attackers can set weak passwords and reduce resistance to subsequent compromise. | Apply one server-side password policy consistently to registration, change, and reset endpoints. | A07 Identification and Authentication Failures | A07 Authentication Failures | Medium to High | Weak-password request, response, resulting login, and secure-mode rejection. |
| Session invalidation failure | `/api/reset`, `vulnerable-session` | Password reset updates the password but leaves existing session records valid. | A stolen or shared session can remain usable after account recovery. | Revoke all existing sessions or increment a server-side session version after reset. | A07 Identification and Authentication Failures | A07 Authentication Failures | High | Two session cookies, old `/account` request after reset, session record states, and secure comparison. |
| URL token exposure | `/reset`, `vulnerable-leak-url` | The reset token is exposed in a query string by design. | Tokens may enter browser history, proxy logs, screenshots, or other URL-bearing records. | Prefer a restricted reset session or minimize exposure; avoid unnecessary URL persistence and use secure transport in real deployments. | A02 Cryptographic Failures; A07 Identification and Authentication Failures | A04 Cryptographic Failures; A07 Authentication Failures | Medium to High | Reset URL, HTTP history, token lifecycle, and comparison with secure response headers. |
| Response token exposure | `/reset`, `vulnerable-leak-response` | The reset page reflects the raw token into its response body. | Tokens may be captured by logging, caches, or downstream processing. | Do not reflect raw tokens; validate server-side and render only necessary state. | A02 Cryptographic Failures; A05 Security Misconfiguration | A04 Cryptographic Failures; A02 Security Misconfiguration | Medium to High | Response body, headers, token value, and secure-mode comparison. |
| Referer token leakage | `/reset`, `vulnerable-leak-referer` | The reset page loads a resource without a restrictive `Referrer-Policy`. | A reset URL may be transmitted in the Referer header to a resource. | Use `Referrer-Policy: no-referrer`, avoid third-party resources on reset pages, and keep tokens out of URLs where possible. | A02 Cryptographic Failures; A05 Security Misconfiguration | A04 Cryptographic Failures; A02 Security Misconfiguration | High | Reset page request, tracking request Referer header, response headers, and secure comparison. |
| Debug-log token leakage | `/forgot-password`, `/events`, `logs/security-events.log` | Debug instrumentation records raw reset tokens. | Anyone with log access may reuse a live reset token. | Never log raw tokens or passwords; redact identifiers and restrict log access. | A09 Security Logging and Monitoring Failures; A02 Cryptographic Failures | A09 Security Logging and Alerting Failures; A04 Cryptographic Failures | High | Local log line, event page, token replay result, and secure-mode redaction proof. |
| Account takeover validation | Affected vulnerable endpoint followed by `/login` and `/account` | A reset authorization or lifecycle control is bypassed. | Synthetic account access is obtained with an attacker-controlled password. | Fix the underlying reset vulnerability, invalidate tokens and sessions, and retest the full flow. | A01 Broken Access Control; A07 Identification and Authentication Failures | A01 Broken Access Control; A07 Authentication Failures | Critical | Authorization/bypass request, password-change result, old-password failure, new-password success, session evidence, and account page. |
